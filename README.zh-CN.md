# SiliconMeter

轻量、低功耗的 Apple Silicon 菜单栏系统监控与本地历史记录工具。**0.1.0** 是本地发布候选版本，尚未公开发布。

## 界面预览

正式截图将在后续版本加入。菜单栏一次显示一项指标，例如 `CPU 23%`、`GPU 91%`、`温度 61°C`、`GPU 功耗 14.0W` 或 `NET ↑ 1.3 MB/s ↓ 12.4 MB/s`。

## 功能

- 菜单栏可选择五项主要指标；简洁弹出窗口展示当前系统遥测。
- 提供 SiliconMeter 正式 App 图标，用于 Finder、“应用程序”和 DMG。
- 每项指标及语言使用固定的菜单栏宽度，数值变化不会推动相邻状态栏项目。
- 从同一份共享快照持续写入本地 SQLite 历史；使用串行批量写入、WAL 和可配置的保留时间。
- 支持 English 和简体中文，可立即切换，并在本地保存语言选择。
- 在本地保留主要指标选择。未签名的 v0.1 不包含“登录时启动”。
- 普通用户即可运行，无需辅助进程、常驻子进程、`powermetrics`、主动网络连接或遥测上传。

## 支持的指标

CPU 总占用及经过验证的性能核/能效核占用；GPU 活跃比例、估算的活跃加权频率与 GPU 功耗；网络下载/上传速率；Tp05/Tg05 温度；虚拟内存与统一内存字段、交换空间、内存压力及系统热状态。Network 的定义是：当前选定外部网络接口实际接收/发送流量的汇总速率。App 只读取原生累计计数器，不发送测试流量；VPN 隧道计数不会与底层链路重复相加。菜单栏中不可用或无效的数值显示为 `—`，不会伪装成零。估算值在弹出窗口和历史记录的质量字段中标明。

## 历史记录

快速样本约每 2 秒记录一次，慢速样本约每 6 秒一次；Network RX/TX 与快速样本共用时间戳、质量和实际测量窗口字段。约每 30 秒批量写入，并在正常退出时刷盘。异常退出可能丢失最近尚未提交的一批数据。弹出窗口提供记录状态、数据库大小、保留时间和**打开数据文件夹**按钮。普通 SQLite 工具可读取已提交历史；参见[v4 表结构、单位与只读查询](docs/HISTORY_SCHEMA.md)。历史记录在两次清理之间可能增长。引入保留时间之前，最终候选版本在 30 分钟内的 SQLite 逻辑大小增加了 344,064 字节，约合 0.688 MB/小时。按这一短期速率推算，1 小时约 0.688 MB、24 小时约 16.52 MB、7 天约 115.61 MB、30 天约 495.45 MB。此前持久文件的估计值为 0.698 MB/小时。这些是估算值，不是容量限制；运行时 WAL 和 SHM 文件还会额外占用临时磁盘空间。可通过**打开数据文件夹**找到 SQLite 文件。v0.1 不降采样历史数据。

## 历史记录保留时间

在“历史记录”中选择 **1 天**（滚动的最近 24 小时）、**7 天**、**30 天**或**永久**。全新安装默认 **30 天**。已有数据库若尚无保留时间设置，则默认**永久**，避免旧历史被静默删除。缩短保留时间前会要求确认；选择“取消”会保留原设置。延长保留时间不能恢复已删除的记录。清理在后台执行，不会自动运行 `VACUUM`。删除旧记录后，显示的数据库大小可能不会立刻下降，因为 SQLite 会复用释放的页面。

## 隐私

所有遥测和历史数据只保存在本机。Network 监控仅读取系统接口计数器，不产生监控流量，也不主动测速。App 没有分析服务、云服务或遥测上传，不按进程归属网络流量，也不收集用户文件内容。数据库保存系统指标和 App 运行元数据，不记录工作负载标签。语言、主要指标和保留时间选择存放在本地 `UserDefaults`，不写入遥测数据库。

## 系统要求

macOS 13 或更新版本的 Apple Silicon Mac，且不在 App Sandbox 中运行。**已测试：Apple M1 Max、macOS 27.0（build 26A428）。**其他 Apple Silicon 芯片和 macOS 版本仅尽力兼容，不保证可用。不需要 root 权限。

## 安装

SiliconMeter v0.1.0 当前以未签名、未公证的开源社区构建形式发布，未经 Apple 验证。源代码可供检查和本地构建。公开下载尚待发布；发布后按以下步骤安装：

1. 从项目的 GitHub Release 下载 `SiliconMeter-0.1.0-arm64.dmg`。
2. 打开 DMG，将 **SiliconMeter.app** 拖入**应用程序**文件夹。
3. 从“应用程序”启动 SiliconMeter。
4. 如果 macOS 阻止首次启动，打开**系统设置 → 隐私与安全性 → 仍要打开**，然后再次确认打开。参见 [Apple 的人工确认说明](https://support.apple.com/zh-cn/102445)。

本机直接构建无法完全复现浏览器下载后的 Gatekeeper 提示。不要全局关闭 Gatekeeper。

## 从源码构建

安装包含 Swift 和 Clang 的 Apple Command Line Tools，然后运行：

```sh
sh app/build.sh
open app/SiliconMeter.app
```

点击菜单栏图标可查看当前遥测、选择主要指标或语言、打开数据文件夹，或退出。App 以辅助应用方式运行，不显示 Dock 图标。未签名的 v0.1 不包含“登录时启动”。定向检查见 [tests/README.md](tests/README.md)；[产品范围](docs/PRODUCT_SCOPE.md)定义 v0.1 的边界。

## 数据位置

数据库位于 `~/Library/Application Support/SiliconMeter/telemetry.sqlite3`。App 运行时可能存在 `-wal` 和 `-shm` 附属文件。实时备份应使用 SQLite 备份 API。外部程序可直接只读查询数据库；App 不提供 HTTP 或 socket API。

## 升级说明

早期本地开发版本使用 `Compute Monitor` 数据目录。打开 SiliconMeter 前请先退出旧 App。首次启动时，若新目录不存在，SiliconMeter 会将旧目录整体迁移。若新旧目录都存在，则保留两者并使用 SiliconMeter 目录；请先查看本地日志，再手动处理冲突。

## 已知限制

IOReport 和 AppleSMC 私有接口的行为可能随系统或硬件更新而变化；不支持的能力会明确显示为不可用。GPU 功耗和加权频率是估算值，尚未经过外部校准。网络接口选择较保守：未报告 Ethernet 类型或链路速率的特殊物理接口可能不会被计入；VPN 隧道流量不单独累加。App 内没有历史图表、进程归属、工作负载分析或自动调优。本地 LLM、编译、渲染等只是通用历史日志的外部使用场景。已有的 v2 数据库可能保留一张不再使用的实验表以避免丢失数据；全新或从 v1 升级的 v4 数据库不会创建它。

## 私有 API 兼容性风险

完整遥测构建刻意不使用 App Sandbox，因为测试中沙盒阻止了 IOReport 和 AppleSMC 访问。未来 macOS 版本可能改变或移除这些私有接口。v0.1.0 社区构建没有 Developer ID 签名，也未经公证。本地 ad-hoc 代码封印只是构建细节，不代表 Apple 信任的开发者身份。
